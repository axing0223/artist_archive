# 图片助手 0.2.0：更新并连接画师库

之前的单图测试已通过；现在扩展可以给本地「画师库.html」提供图片。测试页面仍保留，点击扩展图标可以打开。

## 更新步骤

1. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`。
2. 找到原来安装的扩展，点击「重新加载/刷新」。更新后名称为「画师库 · 图片助手」，版本为 **0.2.0**。不需要重复安装第二个扩展。
3. 打开扩展的「详情」，开启 **允许访问文件网址**。这是为了让连接脚本在本地 HTML 中运行；如果不开，原单图测试可能成功，但画师库仍无法连接。
4. 关闭旧画师库标签页，重新双击项目根目录的 **画师库.html**。不要重命名这个 HTML 文件。
5. 顶栏应显示 **图片助手已连接 · 0.2.0**，再选择原来的数据文件夹。若显示未连接，检查上一步的开关，点击状态按钮重试。

## 正式使用

- 识别候选画师时，附近的预览图片由扩展获取，直接显示在当前画师库里。
- 添加画师时，会尝试把其预览保存进独立画师目录。此后优先读取本地文件。
- 已有画师中以前加载失败的在线图片，可以直接通过扩展查看；点击 **缓存附近预览**，将点击时附近已加载画师的在线图片保存到本地。不扫描或下载全部 2000 人。
- 所有画师在一整页里连续上下滚动，没有分页。离视野较远的卡片只保留占位高度，靠近时再构建卡片和加载图片。
- 点击 **释放临时缓存** 会释放内存中的图片并按需重载当前可见图片，不删除磁盘文件。

## 大量画师的加载与缓存

- 启动只并发读取少量「信息.json」，不把整个库的图片转成 Base64。
- 文件夹里的图片保留为路径；进入视野附近才读文件。缓存未命中时，旧在线图片才通过扩展请求。
- 最多同时加载 3 张图片；已离开视野的排队任务会取消，显示用的 Blob URL 会撤销。
- 临时 Blob 缓存最多 64 张且不超过 32 MB，最久未使用的条目优先淘汰。这不是整个浏览器进程的总内存上限；解码后的可见图片、资料、浏览器自身也会占内存。
- 已保存的本地图片是你的持久资料，不因内存缓存淘汰而删除。再次打开、滚动回来时可从本地读取。
- 卡片展示前 5 张预览；上传超过 5 张的画师可在编辑页查看全部，图片仍按需加载。
- 数量、备注等修改只写变化的画师资料，不重复读取和写入所有图片。
- 大库优先复制整个「数据」文件夹备份。JSON 导出逐张读图写入，避免同时组装整个图像库；JSON 导入限制为 100 MB，更大备份请使用完整数据文件夹。

## 权限与限制

扩展联网权限仍仅限 `danbooru.donmai.us` 和 `cdn.donmai.us`。增加了文件页面连接脚本，但脚本只在名为「画师库.html」且具有画师库标识的顶层页面启用。后台再次校验页面来源，只提供 CDN 图片获取；不提供任意本地文件读取，不读取或导出 Cookie，不改变浏览器安全设置。

每次单图请求最多等待约 20 秒，正式连接单张图片限制 8 MB。服务器仍可能拒绝某些请求，失败会提示并保留原来源链接，30 秒内避免反复自动请求同一失败图片。

本轮代码测试包括模拟的 2000 位画师/10000 张图片、内存缓存淘汰、连续滚动挂载释放、连接消息往返、权限边界、取消和备份。实际 Chrome 文件页面连接仍需按以上步骤更新后确认；模拟耗时不是实际磁盘或网络性能承诺。
