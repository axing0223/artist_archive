# 图片助手 0.9.0：扩展里直接开画师库

## 首次安装

**从没装过**就照这里做；已经装过、只是要更新，跳到下面的「更新步骤」。

1. 打开 Chrome 的 `chrome://extensions`（Edge 是 `edge://extensions`）。
2. 打开右上角的 **开发者模式**（Developer mode）。不打开的话下一步的按钮不会出现。
3. 点 **加载已解压的扩展程序**（Load unpacked）。
4. 在弹出的选择框里选中本仓库里的 **`图片取图扩展`** 这个文件夹
   （**注意选文件夹本身，不要进去选里面的某个文件**，也不要选仓库根目录）。
5. 列表里会出现「**画师库 · 图片助手**」，版本 **0.9.0**，没有红色报错。
6. （可选）想用「双击 `画师库.html`」那条路，就点扩展的「详情」→ 打开 **允许访问文件网址**；
   只用扩展页打开画师库的话，不用打开这个开关。

装好后点工具栏上的扩展图标：应该直接看到画师库页面。第一次会要你选一个数据文件夹。

**这两步是新手最容易卡住的地方：**

- **开发者模式没开** → 看不到「加载已解压的扩展程序」。它每次重开浏览器都可能需要重新打开
  （Chrome 对未打包扩展的常规行为）。
- **选错了文件夹** → 报「清单文件缺失或不可读」。要选的是 `图片取图扩展` 本身，
  也就是**直接包含 `manifest.json` 的那一层**。

## 装完先确认这三件事

| 检查 | 应该看到 | 不对的话 |
|---|---|---|
| 扩展列表 | 「画师库 · 图片助手」0.9.0，无红色「错误」按钮 | 有错误就点进去看；改了 `app/` 没跑 `npm run build` 是最常见原因 |
| 点扩展图标 | 直接打开画师库页面（不是旧的测试页） | 没反应就重新加载扩展 |
| 打开一个文件夹 | 顶部显示文件夹名，页面出现画师列表或「画师库还是空的」 | 报「请选择现有「数据」文件夹」说明选错了层级 |

选文件夹时：**空文件夹**会新建一个库；**已有的「数据」文件夹**会原样读进来。
选之前编辑功能是锁着的，这是有意的——避免误把空库覆盖到已有数据上。

## 更新步骤

1. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`。
2. 找到原来安装的扩展，点击「重新加载/刷新」。更新后名称为「画师库 · 图片助手」，版本为 **0.9.0**。不需要重复安装第二个扩展。
3. 想继续用「双击 HTML」那条路，就照旧打开「详情」→ 开启 **允许访问文件网址**；只用扩展页打开画师库的话，这一步可以不开。
4. 点扩展图标：应该直接看到画师库页面，再选择原来的数据文件夹。若没反应或还看到旧的测试页，说明没重新加载扩展。

## 卸载与数据

卸载扩展**不会**删掉你的数据文件夹——数据始终在你选的那个文件夹里。
想看详细的卸载步骤、以及**怎么完整备份**，见仓库根目录的 [`隐私说明.md`](../隐私说明.md)。
要点：留档的唯一完整方式是**复制整个「数据」文件夹**（JSON 与图片一起）。

## 这一版做了什么

0.9.0 起，**点扩展图标就会打开画师库**（跑在扩展页里）；已经开着就切到那个标签页，不会开一堆。扩展页本身就是扩展，带 host_permissions 的 `fetch` 能带上站点 Cookie，所以取图、生图、查额度全部由页面直连——不再经过 content script 与后台的消息通道，也不需要「允许访问文件网址」。

**右键菜单「添加到画师库」**：在任意网页上选中一段文字（画师标签、别名、Danbooru 编号或主页链接），右键 → 「添加到画师库」，它会**直接按这段文字建一张新画师卡片**（等于「批量导入名字」加一位：补 Danbooru 编号、作品总数、3 张作品缩略图）。

- **全程不会自己打开画师库页面**。画师库已经开着就就地建卡；没开着就先把这件事记下来（会话存储，内存态），等你下次打开画师库时自动添加。
- 提示分三种：**琥珀色「正在尝试加入画师库…」**（带闪动小圆点，一直显示到你看到结果）→ **绿色**「已添加「XX」· Danbooru #编号 · N 张作品」或**红色**「没能添加画师 + 原因」；页面没开着时是**蓝色「已记下这次添加」**，点它打开画师库就会立刻执行。
- **点提示**：绿色会打开（或切到）画师库并**自动滚到刚建的那张卡片**、闪一下边框。红色**不会**替你填任何输入框——它只把画师库打开，要手动加得自己点页面上的「添加画师」。页面刚被打开、还在加载时，定位命令会排队等它加载完再执行。
- 定位失败、候选不唯一、已经在库里、取不到作品、没有可用的数据文件夹——这几种都**不会建卡**，红提示会写明是哪一种。选中的是一整段话（例如「modare (@modare_105704)」）时，整段没匹配上会再用第一个像标签的词试一次。
- 真正写文件必须由画师库页面完成（数据在你选的文件夹里，只有页面拿得到那套 File System Access 逻辑），所以「静默」= **不打断你、不切换页面、不自己开页面**。

权限：`contextMenus`（右键菜单）、`storage`（页面没打开时的待办交接，内存态）、`scripting` + `activeTab`（只在**你主动用菜单的那一页**临时注入漂浮提示，不申请全站访问）。

`file://` 那条路原样保留：双击「画师库.html」照样能用，只是那条路仍然要开「允许访问文件网址」、仍然由后台代取（页面受跨站限制）。两条路读写同一个数据文件夹，随便换着用。注意右键菜单只会投递给**扩展页里的**画师库——`file://` 那份收不到扩展消息。

单图取图测试页还在：**在扩展图标上右键 → 选项**，或者访问 `chrome-extension://<扩展ID>/test.html`。某张缩略图在别处加载失败时，把那个地址填进去就能判断问题出在取图通道还是站点本身。

## 更新步骤

1. 打开 Chrome 的 `chrome://extensions`，或 Edge 的 `edge://extensions`。
2. 找到原来安装的扩展，点击「重新加载/刷新」。更新后名称为「画师库 · 图片助手」，版本为 **0.9.0**。不需要重复安装第二个扩展。
3. 想继续用「双击 HTML」那条路，就照旧打开「详情」→ 开启 **允许访问文件网址**；只用扩展页打开画师库的话，这一步可以不开。
4. 点扩展图标：应该直接看到画师库页面，再选择原来的数据文件夹。若没反应或还看到旧的测试页，说明没重新加载扩展。

扩展里的画师库是构建时从 `app/` 镜像过去的（`图片取图扩展/app/`，MV3 的扩展页禁止内联脚本，所以扩展里必须是多文件那一份）。**改动 app 里的任何文件后，先跑一次 `npm run build` 再重新加载扩展**；`npm test` 会校验镜像与源码是否一致。

0.4.1 增加了一条只读的额度查询通道：网页可以请求 `image.novelai.net` 或 `api.novelai.net` 上的 `/user/subscription`（就这一个路径），用来显示套餐、Opus 免费额度剩余与 Anlas 点数。为此新增 `https://api.novelai.net/*` 权限。**不重新加载扩展就查不到额度**，网页会提示需要 0.4.1；「不使用点数」模式下查不到额度就不允许生成。

0.4.0 新增 `https://image.novelai.net/*` 权限，用于代画师库发一次文生图请求：地址被写死成 `/ai/generate-image`，页面无法让扩展去请求别处；token 由页面交给扩展后放进 `Authorization` 头，不写日志、不回传、不落盘。

0.3.2 起，画师的作品列表、画师检索与数量查询改由扩展代为请求，不再由网页匿名直连。原因是站点对 `file_url`、`large_file_url`、`preview_file_url` 标注了 "Only shown if visible to user"——匿名请求拿不到这些图片地址，带登录 Cookie 才拿得到。**更新到 0.3.2 必须重新加载扩展**，否则这条通道不存在，网页会自动退回匿名直连（能取到数量，但取不到图片地址）。

0.3.1 起，接入扩展的判定改为页面自身的 `<meta name="artist-library" content="v1">` 标记，不再要求文件必须叫「画师库.html」。这样 `工具/回填作品.html` 这类本地工具页也能取图。

0.3.0 换了取图协议：扩展与网页必须同版本，旧版扩展配新版网页会在点开作品时报「扩展返回的图片尺寸信息无效」。重新加载扩展即可。

## 正式使用
- 识别候选画师时，会按页取回最近 21 张作品（用「← 上一页 / 下一页 →」翻页，勾选跨页保留），每张都带勾选框；勾选的作品在添加时下载缩略图。
- 主页面与候选区只加载缩略图（360×360）。点开作品时才临时取回原图放大显示，不再写入磁盘；单张上限 50 MB，关掉页面即从内存释放。
- 旧版本加进来的画师没有保存原图地址，点开时会先按作品编号向站点查询再取图；查不到就继续显示缩略图并说明原因。
- 添加画师时，会尝试把勾选作品的缩略图保存进独立画师目录。此后优先读取本地文件。
- 已有画师中以前加载失败的在线图片，可以直接通过扩展查看；滚到附近时程序会自动把已加载画师的在线缩略图缓存到本地，不需要手动操作，也不会扫描或下载全部 2000 人。
- 所有画师在一整页里连续上下滚动，没有分页。离视野较远的卡片只保留占位高度，靠近时再构建卡片和加载图片。
- 内存里的图片由程序自动管理：离开视野就释放、回到视野按需重载，磁盘文件不动，不需要手动清理。

## 大量画师的加载与缓存

- 启动只并发读取少量「信息.json」，不把整个库的图片转成 Base64。
- 文件夹里的图片保留为路径；进入视野附近才读文件。缓存未命中时，旧在线图片才通过扩展请求。
- 最多同时加载 3 张图片；已离开视野的排队任务会取消，显示用的 Blob URL 会撤销。
- 临时 Blob 缓存最多 64 张且不超过 32 MB，最久未使用的条目优先淘汰。这不是整个浏览器进程的总内存上限；解码后的可见图片、资料、浏览器自身也会占内存。
- 已保存的本地图片是你的持久资料，不因内存缓存淘汰而删除。再次打开、滚动回来时可从本地读取。
- 卡片展示前 5 张预览；上传超过 5 张的画师可在编辑页查看全部，图片仍按需加载。
- 数量、备注等修改只写变化的画师资料，不重复读取和写入所有图片。
- 大库优先复制整个「数据」文件夹备份。JSON 导出逐张读图写入，避免同时组装整个图像库；JSON 导入限制为 100 MB，更大备份请使用完整数据文件夹。

## 权限与限制

扩展联网权限仅限 `danbooru.donmai.us`、`cdn.donmai.us`，以及 0.4.0 起的 `image.novelai.net` 与 0.4.1 起的 `api.novelai.net`。增加了文件页面连接脚本，脚本只在带有画师库标识（`meta[name="artist-library"]`）的本地顶层页面启用；后台再次校验来源必须是本扩展注入的、顶层框架的 `file:` 页面。0.3.2 增加了一条只读的接口通道：网页可以请求 `danbooru.donmai.us` 上以 `.json` 结尾的地址，用于取画师与作品数据；非该域名、非 https、带账号密码或自定义端口的地址一律拒绝，接口返回也限制在 8 MB 内。0.4.0 增加的生图通道只认写死的 `https://image.novelai.net/ai/generate-image`，请求体由网页拼好、大小限制 200 KB；0.4.1 增加的额度通道只认 `/user/subscription`，返回原样 JSON（上限 2 MB）由网页解释。两者都只做 token 形状检查后放进请求头，服务端的错误原话会带回去但不记日志。不提供任意本地文件读取、不提供任意 POST 代理，不读取或导出 Cookie，不改变浏览器安全设置。

单次请求最多等待约 60 秒（生图 180 秒），单张图片上限 50 MB。图片以分块方式传回网页（每块 4 MB），避免大图撑爆一次消息；分块中途扩展被回收时会提示重新获取，不会返回残缺图片。服务器仍可能拒绝某些请求，失败会提示并保留原来源链接，30 秒内避免反复自动请求同一失败图片。

生图返回的是 zip 压缩包，网页侧自己解包取第一张图片（扩展不解析图片内容）。生成前网页会先确认额度：「不使用点数」时步数与尺寸会被压进 Opus 免费范围，并且要求额度查得到且没见底，否则不允许生成；「使用点数」时按填的参数原样发出，点数见底又超出免费范围才会拦住。token 无效、Anlas 不足、配额超限、模型需要 Opus 等情况都会把 NovelAI 的原话显示在网页底部的状态栏里，不会静默失败。

本轮代码测试包括模拟的 2000 位画师/10000 张图片、内存缓存淘汰、连续滚动挂载释放、连接消息往返、权限边界、取消和备份，以及生图请求体（V5 的 `params_version`、必带的 `v4_prompt`、`cfg_rescale`、透明背景三件套）、免费额度换算与钳位、点数门禁、额度查询的域名回退与缓存、zip 解包、token 与端点/路径的拒绝规则、测试风格图的文件命名与清理边界。实际 Chrome 文件页面连接仍需按以上步骤更新后确认；模拟耗时不是实际磁盘或网络性能承诺。真实调用 NovelAI 需要你自己的 token，自动化测试只用假的传输层，不会消耗 Anlas。
